# LinkGuard 발표·시연 대본

총 10~12분을 목표로 하며 과제의 최대 15분과 3개 이하 시연 시나리오에 맞춘 구성입니다. 성능 설명에는 발표 시점의 `docs/model-report.md`와 실제 화면의 측정값을 사용합니다.

## 1. 소개 — 약 1분

“LinkGuard는 의심스러운 링크를 입력하면 머신러닝이 계산한 피싱 의심 점수와 URL 구조를 함께 보여주는 서비스입니다. 주소 앞부분에 익숙한 서비스 이름이 있더라도 실제로 어느 도메인에 속한 주소인지 구분하기 어렵다는 문제에서 출발했습니다. URL 검사에 공식 도메인 비교와 한국어 설명을 추가했습니다.”

## 2. 데이터와 구현 — 약 2분

“UCI의 PhiUSIIL 공개 데이터를 사용했습니다. 원본에는 URL과 웹페이지에서 추출한 특징이 함께 있지만, 저희는 새 주소에서도 같은 방식으로 계산할 수 있도록 등록 가능 도메인의 문자열에서 특징을 추출했습니다. 숫자 특징을 이용한 로지스틱 회귀·랜덤 포레스트와, 도메인 철자의 2~5글자 조합을 이용한 TF-IDF 로지스틱 회귀를 비교했습니다.”

“같은 도메인의 주소가 학습과 평가에 섞이지 않도록 도메인 그룹 단위로 분리했습니다. 각 실행의 모델과 판정 기준은 검증 데이터에서 선택하고 평가 분할의 결과는 별도로 기록했습니다. 개발 중 수집 편향을 발견해 특징 범위를 개선한 뒤 같은 평가 분할을 다시 사용했으므로, 결과는 개발 반복 후의 내부 평가라고 설명합니다.”

전처리 제외 건수, 분할별 건수, 최종 모델은 모델 보고서의 실제 값을 보여줍니다. 원본 전체 건수와 학습에 사용한 건수를 구분합니다.

## 3. 시나리오 1: 문자에서 링크 검사 — 약 2분

```text
[교육용 예시]
안내: https://example.org/notice
계정 확인: https://example.org.login-check.example.com/auth
```

“문자를 넣으면 링크를 추출해 각각 검사합니다. 문자 전체의 사기 여부를 판단하는 것이 아니라 문자 속 링크를 분석한 결과입니다. 이 예시는 구조를 설명하기 위한 주소이며 실제 피싱 탐지 성능을 증명하는 샘플은 아닙니다.”

모델 점수와 구조 관찰을 구분해 보여줍니다. 예시의 모델 점수를 미리 정해진 정답처럼 설명하지 않습니다.

## 4. 시나리오 2: 공식 도메인 비교 — 약 2분

공식 도메인에 `example.org`를 입력합니다.

“두 번째 주소 앞부분에도 example.org라는 문자열이 있습니다. 하지만 실제 등록 가능 도메인은 example.com입니다. 화면에서 이 차이를 구분하고 한국어로 설명합니다. 이 기능은 모델 점수와 별도로 작동합니다.”

“공식 도메인과 다르다고 무조건 피싱으로 단정하지는 않습니다. 정상적인 외부 인증이나 결제 서비스일 수도 있어 추가 확인을 안내합니다.”

## 5. 시나리오 3: 탐지 기준 비교 — 약 2분

모델 평가 화면에서 검증 데이터의 판정 기준을 바꿉니다.

“기준을 낮추면 더 많은 주소를 의심으로 분류합니다. 잡아낸 피싱뿐 아니라 정상을 잘못 분류한 오탐도 확인해야 합니다. 반대로 기준을 높이면 오탐을 줄일 수 있지만 놓치는 피싱이 늘어날 수 있습니다.”

TP·FP·TN·FN과 지표 변화를 보여줍니다. 최종 평가 보고값은 검증 데이터에서 고정한 기준으로 얻었다는 점을 설명합니다.

## 6. 결과와 한계 — 약 1분

“공개 데이터로 모델을 직접 학습하고 주소 검사 화면까지 연결했습니다. 공식 도메인 비교, 문자 속 링크 추출, 탐지 민감도 비교를 통해 결과를 이해하도록 구성했습니다.”

“URL 문자열만 분석하므로 웹페이지 내용, 단축 URL의 최종 목적지, 최신 위협 정보까지 확인하지는 않습니다. 낮은 의심 점수가 안전을 보장하지 않으며, 과거 공개 데이터의 성능과 실제 운영 성능을 구분해야 합니다.”

“데이터 점검에서 정상 URL이 모두 HTTPS이고 경로와 쿼리가 비어 있는 수집 편향을 확인했습니다. URL 형식만으로 답을 맞히는 지름길을 줄이기 위해 현재 모델은 등록 가능 도메인의 문자열 특징만 사용합니다. 같은 도메인의 경로나 HTTP/HTTPS를 바꿔도 모델 점수는 같습니다. 그 대신 정상 도메인의 침해나 특정 경로의 악성 동작은 탐지할 수 없다는 한계를 설명합니다.”

## 예상 질문

| 질문 | 답변 핵심 |
| --- | --- |
| 기존 서비스와 무엇이 다른가요? | 최초성·성능 우위 주장이 아니라 도메인 비교·한국어 설명·민감도 학습을 묶은 서비스 구성 |
| 머신러닝을 사용한 부분은? | URL 특징으로 학습한 분류 점수. 도메인 비교는 별도 규칙 |
| 점수 80은 피해 확률 80%인가요? | 아니며 보정된 피해 발생 확률로 해석하지 않음 |
| 실제 악성 사이트에 접속하나요? | 아니며 문자열만 분석. 학습 데이터 다운로드는 공식 제공처 이용 |
| 정확도만 보면 되나요? | 피싱 재현율, 정밀도, 정상 오탐률, 미탐을 함께 확인 |
| 같은 사이트를 학습·평가하면? | 과대평가 위험이 있어 등록 가능 도메인 그룹 분리 |
| 단축 링크·해킹된 정상 사이트도 잡나요? | 문자열만으로 확인할 수 없는 경우가 있어 추가 분석 필요 |
